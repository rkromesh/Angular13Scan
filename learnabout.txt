Usage
bash

node angular-ast-scan.js --src ./src --tsconfig ./tsconfig.json --out ./arch-report

Flags
Flag	Default	Description
--src <dir>	./src	Source root to scan
--tsconfig <file>	./tsconfig.json	tsconfig for path mapping and compiler options. Important — this is how path aliases (@app/*) resolve
--out <dir>	./arch-report	Output directory
--include-tests	off	Include *.spec.ts files
--max-nodes <n>	5000	Safety cap on nodes per graph
--mermaid-max <n>	150	Max nodes rendered in a single Mermaid diagram (JSON always has the full graph)
--fail-on <csv>	—	Exit non-zero if the named checks find issues. Keys: httpOutsideRoot, repeatedShared, duplicateSingletons, leakyRoot, forFeatureWithoutRoot
Example — CI gate
bash

node angular-ast-scan.js \
  --src ./src \
  --tsconfig ./tsconfig.json \
  --out ./arch-report \
  --fail-on httpOutsideRoot,forFeatureWithoutRoot

This fails the build (exit code 2) if HttpClientModule is imported outside AppModule or if any forFeature runs without a visible forRoot — catching provider-scoping regressions before merge.
Example — scan a single large feature

For very large src/, you can split the scan and merge reports:
bash

node angular-ast-scan.js --src ./src/app/feature-orders --out ./arch/orders
node angular-ast-scan.js --src ./src/app/feature-billing --out ./arch/billing

Each architecture-model.json is a plain map of nodes/edges and can be merged.
Reading the report cold — 10-minute onboarding path

    Open ARCHITECTURE-REPORT.md §8 — the ordered start guide.

    graphs/modules.mmd — see how NgModules wire up. Locate AppModule; follow its imports to CoreModule and SharedModule; then to feature modules.

    graphs/routing.mmd — every arrow leaving a routing file is a business feature. Pick one and read its feature module next.

    graphs/services.mmd — follow arrows into a service to see its consumers; arrows out to see its collaborators.

    graphs/api.mmd — filter by a feature file to see exactly which endpoints that feature touches.

    graphs/ngrx.mmd — confirm forRoot runs before any forFeature.

Section 9 of the report documents exactly what the scanner cannot prove — always read it before trusting a graph for a high-risk change.
How it works (short version)

    Loads tsconfig.json via ts.parseJsonConfigFileContent and creates a ts.Program over all .ts files in --src.

    Walks the AST once to classify every class by its decorator: @NgModule, @Component, @Directive, @Pipe, @Injectable.

    For NgModules, extracts declarations/imports/exports/providers and resolves each entry through the compiler's symbol table (checker.getSymbolAtLocation → checker.getAliasedSymbol → ts.resolveModuleName). This is what makes aliases and re-exports work.

    For routing files, detects RouterModule.forRoot/forChild and extracts loadChildren/loadComponent targets from arrow callbacks.

    For components, reads templateUrl (from disk) or inline template and matches tag selectors against the declared-component selector registry.

    For injectables, walks constructor parameter type references and resolves each to its declaring file.

    For API calls, detects HttpClient method calls and extracts verb + URL.

    For NgRx, greps for StoreModule.*, EffectsModule.*, createAction, createReducer, createSelector.

    Emits Markdown + JSON + six .mmd files.

Limitations — read before relying on the output

Static analysis of Angular is heuristic, not proof. The scanner is explicit about what it cannot do:

    Dynamic import(expr) — imports with computed strings cannot be resolved; flagged [VERIFY].

    Runtime-generated routes — router.navigate targets, route guards returning to constructed URLs, and route configs built in code cannot be mapped statically.

    Interceptor execution order — the scanner inventories interceptors (G4) but the actual HTTP chain at runtime depends on HTTP_INTERCEPTORS provider order in the root module.

    Template analysis — tag selectors match well; attribute selectors, ngComponentOutlet, ng-template content projection, and structural directives need manual review.

    API URLs composed at runtime — http.get(\base/orders/base/orders/{id}`)` is flagged dynamic.

    Business flows — which API feeds which state, which state feeds which UI, and which UI action triggers which effect — requires reading NgRx effects/reducers by hand or running the application. The scanner is a map, not a trace.

    Path aliases — resolved only if tsconfig.json paths are configured and passed via --tsconfig. Otherwise they show as ?:name edges with [VERIFY].

If you need business-flow reconstruction, this is the wrong tool — that requires either runtime tracing (OpenTelemetry, Angular DevTools) or manual code reading of NgRx effects and component reducers.

GitHub Actions
yaml

name: Architecture Scan
on: [pull_request]

jobs:
  arch-scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '18' }
      - run: npm ci
      - run: npm install --no-save typescript@4.9
      - run: node angular-ast-scan.js --src ./src --out ./arch-report --fail-on httpOutsideRoot,forFeatureWithoutRoot
      - uses: actions/upload-artifact@v4
        if: always()
        with:
          name: arch-report
          path: arch-report/

FAQ

Does it modify my source?
No. It reads files only and writes outputs to --out.

Does it run my application?
No. It does not start Angular, Node, or any server. It only parses .ts files.

Will it work on an src/ with 2,000 files?
Yes. TypeScript's Program is built for repositories of this scale. If parsing takes too long, use --src on a single top-level feature folder and merge the resulting architecture-model.json files.

Why does it need --tsconfig?
To resolve path aliases (@app/core/*) and to match the project's module resolution strategy. Without it, alias imports show as ?:name with [VERIFY] tags instead of resolved file edges.

Can it reconstruct business flows?
No. It reconstructs declared dependencies and architectural relationships. Business flows (API → state → UI sequencing) require runtime tracing or manual reading of NgRx effects and reducers.

Can I extend it?
Yes. The script is a single file with clearly separated "passes" (Pass 1–7). Each pass adds edges to a graph object (G.modules, G.routing, etc.). Add a pass or a check, add a Mermaid render call, and it appears in the report.
